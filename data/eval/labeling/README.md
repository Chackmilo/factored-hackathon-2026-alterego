# Labeling the held-out suite

For the four team members who label `data/eval/heldout_cases.jsonl` (TQ-018; decision log row "Suite de evaluación"). Its expectations are design labels written from the spec; your independent labels replace them.

1. Take one sheet each, `labels_A.csv` to `labels_D.csv` (75 cases per sheet), and agree in the team chat who is A, B, C and D.
2. Label alone. Before you finish, do not open the suite file, its design labels or any evaluation report: 50 cases sit on two sheets, and Cohen's kappa is computed on them.
3. Decide each case as the correct system should behave under the policy (`docs/specs/dispute-policy-v2.3.md`) and the brief (section 5).
4. Fill the label columns:

| Column | Values |
| --- | --- |
| `final_outcome` | `AUTONOMOUS_RESOLUTION`, `CLARIFICATION_REQUIRED`, `SAFE_POLICY_ABSTENTION`, `MANDATORY_HITL_ESCALATION`, or `REJECTED` for a request the API must refuse |
| `escalation_reason` | the policy reason when there is one: `AMOUNT_EXCEEDS_500_USD`, `HIGH_FRAUD_RISK_SCORE`, `MULTIPLE_CHARGES_48H`, `SEVERE_DISTRESS`, `REGULATOR_OR_LEGAL_CITING`, `UNRESOLVED_AFTER_CLARIFICATIONS`, `OUT_OF_POLICY_WINDOW`, `NOT_DISPUTABLE_CHARGE`, `OUT_OF_SCOPE_INTENT`, `DATA_ERROR_FUTURE_DATE`, `DATA_GAP_AMOUNT_USD`, `DATA_GAP_CUSTOMER_PROFILE`, `ACTION_VERIFICATION_FAILED`, or `SYSTEM_OF_RECORD_UNAVAILABLE` when a bank read fails or times out (before the policy decides, or while listing the charges again after a lock answer); else empty |
| `requires_human`, `case_opened`, `credit_candidate` | `yes` or `no` |
| `lock_status` | `locked`, `refused`, `offered`, or empty when no lock is offered |
| `reply_language` | `es` or `pt` |
| `comment` | anything a reviewer should know |

5. Commit your sheet. When the four are in, run `docker compose run --rm dev python -m src.eval.labeling kappa` (or `uv run python -m src.eval.labeling kappa`), adjudicate the disagreements together, and write the adjudicated labels into the suite. The inputs stay as frozen; the new file gets a new SHA-256 and a note in the decision log.

The sheets are generated by `python -m src.eval.labeling export` with seed 20260930; regenerating them overwrites your labels.
